# 角色與權限矩陣

本文件定義 MVP 階段的系統角色、群組角色與主要操作權限。原則是先把邊界切清楚，再由 API 與前端各自落實。

## 1. 權限原則

- 系統角色與群組角色分開判斷
- `system_admin` 角色不可直接參與聊天
- 聊天使用者可建立與參與對話
- 群組內權限由 `owner`、`admin`、`member` 三種角色控制
- 未登入者不可存取聊天與管理功能

## 2. 系統角色

### 2.1 角色定義

- `guest`：未登入使用者
- `user`：一般聊天使用者
- `system_admin`：系統管理員

### 2.2 系統角色權限矩陣

| 操作 | guest | user | system_admin |
| --- | --- | --- | --- |
| 瀏覽首頁 | 允許 | 允許 | 允許 |
| 呼叫健康檢查 API | 允許 | 允許 | 允許 |
| 呼叫外部系統註冊 API | 不適用 | 不適用 | 不適用 |
| 呼叫外部系統登入 API | 不適用 | 不適用 | 不適用 |
| 登入 Web | 允許 | 已登入不適用 | 允許 |
| 查看個人聊天列表 | 拒絕 | 允許 | 拒絕 |
| 進入一對一對話 | 拒絕 | 允許 | 拒絕 |
| 進入群組對話 | 拒絕 | 允許 | 拒絕 |
| 傳送文字訊息 | 拒絕 | 允許 | 拒絕 |
| 傳送圖片 | 拒絕 | 允許 | 拒絕 |
| 傳送一般檔案 | 拒絕 | 允許 | 拒絕 |
| 建立群組 | 拒絕 | 允許 | 拒絕 |
| 查詢自己的裝置紀錄 | 拒絕 | 允許 | 不適用 |
| 查詢任意使用者裝置紀錄 | 拒絕 | 拒絕 | 允許 |
| 維護任意使用者 IP 白名單 | 拒絕 | 拒絕 | 允許 |
| 建立其他 `system_admin` | 拒絕 | 拒絕 | 允許 |

### 2.3 補充規則

- `system_admin` 與 `user` 不應混用於同一登入身分。
- `system_admin` 與 `user` 完全分離，不可共用同一帳號身分。
- 若帳號被標記為 `system_admin`，該帳號不得加入任何一對一或群組對話。
- 外部系統註冊與登入 API 屬系統對系統介接，不屬於 `guest`、`user`、`system_admin` 的 Web 操作權限範圍。

## 3. 群組角色

### 3.1 角色定義

- `owner`：群組擁有者
- `admin`：群組管理者
- `member`：一般群組成員

### 3.2 群組角色權限矩陣

| 操作 | owner | admin | member |
| --- | --- | --- | --- |
| 查看群組訊息 | 允許 | 允許 | 允許 |
| 傳送文字訊息 | 允許 | 允許 | 允許 |
| 傳送圖片 | 允許 | 允許 | 允許 |
| 傳送一般檔案 | 允許 | 允許 | 允許 |
| 邀請成員加入群組 | 允許 | 允許 | 拒絕 |
| 移除一般成員 | 允許 | 允許 | 拒絕 |
| 提升成員為群組 admin | 允許 | 拒絕 | 拒絕 |
| 降級群組 admin 為 member | 允許 | 拒絕 | 拒絕 |
| 轉移 owner 身分 | 允許 | 拒絕 | 拒絕 |
| 修改群組名稱 | 允許 | 允許 | 拒絕 |
| 解散群組 | 允許 | 拒絕 | 拒絕 |

### 3.3 補充規則

- `owner` 必須且只能有一位。
- `admin` 可有多位。
- `member` 不可管理其他成員。
- `admin` 可管理一般成員，但不可變更 `owner` 權限。
- 群組角色僅對該群組有效，不影響系統角色。

## 4. 建議 API 權限判斷

### 4.1 系統層

- 未登入時，聊天與管理 API 一律回 `401 UNAUTHORIZED`
- 已登入但角色不足時，回 `403 FORBIDDEN` 或 `403 INSUFFICIENT_ROLE`
- `system_admin` 試圖進入聊天功能時，回 `403 SYSTEM_ADMIN_CANNOT_CHAT`

### 4.2 群組層

- 非成員存取群組時，回 `404 GROUP_NOT_FOUND` 或 `403 FORBIDDEN`
- 成員角色不足時，回 `403 INSUFFICIENT_ROLE`
- 重複邀請已存在成員時，回 `409 MEMBER_ALREADY_EXISTS`
